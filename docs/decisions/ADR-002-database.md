# ADR-002: База данных — PostgreSQL + Prisma

**Status:** Proposed
**Date:** 2026-09-09
**Deciders:** Владелец проекта

## Context

Нужна БД для финансового приложения: реляционные данные (пользователи, счета, активы, транзакции, позиции, доходы, расходы), ACID-транзакции (критично для книги), мультивалютность, целочисленные деньги, история цен.

## Decision

Использовать **PostgreSQL** как основную БД и **Prisma** как ORM.

## Options Considered

### Option A: PostgreSQL + Prisma — выбрано
| Dimension | Assessment |
|---|---|
| Complexity | Low-Medium |
| Cost | Низкий (self-host) / управляемый (Neon, Supabase, RDS) |
| Scalability | Высокая |
| Team familiarity | Стандартный навык |

**Pros:** ACID-транзакции (критично для ledger); надёжность; JSONB для гибких полей; Prisma даёт типобезопасный доступ и миграции; большой экосистемный выбор.
**Cons:** нужен управляемый хостинг или self-host; Prisma — абстракция, требует знания SQL для сложных запросов.

### Option B: SQLite
| Dimension | Assessment |
|---|---|
| Complexity | Low |
| Cost | Нулевой |
| Scalability | Низкая |
| Team familiarity | Высокая |

**Pros:** ноль конфигурации, встроенная.
**Cons:** ограниченная конкурентная запись, нет управляемого продакшн-хостинга. Не подходит для многопользовательского веб-приложения.

### Option C: MongoDB
| Dimension | Assessment |
|---|---|
| Complexity | Medium |
| Cost | Средний |
| Scalability | Высокая |
| Team familiarity | Средняя |

**Pros:** гибкая схема.
**Cons:** данные реляционные (транзакции ↔ позиции ↔ активы); ручные join'ы и дублирование. Не подходит для транзакционной книги.

## Trade-off Analysis

Данные финансового приложения по своей природе реляционные и требуют ACID (особенно единая книга транзакций). PostgreSQL — лучший баланс надёжности, транзакций и экосистемы. Prisma ускоряет разработку и даёт типобезопасность. SQLite — только для локального прототипа, MongoDB — не подходит по модели данных.

## Consequences

- **Деньги хранить как целые числа** в минимальных единицах (копейки/сатоши) или `DECIMAL` — **не `float`** (ошибки округления недопустимы в финансах).
- Все суммы сопровождаются кодом валюты (ISO 4217).
- Prisma-миграции версионируются в репозитории.
- Для сложных агрегаций (стоимость портфеля) можно использовать raw SQL/материализованные представления.
