# Создать таску

Цель: один файл-бриф, по которому другой агент может сделать работу **без догадок**.

Сохрани в `.agents/tasks/<kebab-name>.md` по шаблону [templates/task.md](templates/task.md).

## Шаги (по порядку)

### 1. Пойми задачу
- **Цель** — что должно получиться.
- **Не входит** — что сознательно не делаем.
- **Готово, когда** — чек-лист приёмки (DoD).

### 2. Собери факты (сначала docs, потом код)
Читай сверху вниз. В код лезь только если docs мало:

1. `README.md`, `docs/README.md`
2. `docs/features/` — нужный модуль
3. `docs/architecture/` — правила, модель, ввод
4. `docs/api/contract.md` — если меняется API
5. `docs/decisions/ADR-*.md` — если есть решение по теме
6. Код — пути файлов фронт / бэк / БД

В таску пиши **ссылки на docs** и **пути к файлам**.

### 3. Оцени сложность

| Уровень | Когда так | Модель |
|---|---|---|
| **S** | мелкий фикс, текст, одна функция | быстрая / дешёвая |
| **M** | фича в существующем модуле, эндпоинт, контракт | обычная |
| **L** | домен / миграция / фронт+бэк+БД вместе | мощная |
| **XL** | новая подсистема, архитектура | самая мощная + разбить на части |

Напиши **почему** выбран уровень.

### 4. Тесты
- Нужны? да/нет + почему.
- Какие сценарии (unit / e2e / интеграция).
- Команды: `pnpm test`; при типах/сборке ещё `pnpm typecheck`, `pnpm build`.

### 5. Скиллы
- Нужные из `.agents/skills/` и `~/.agents/skills/`.
- Нет подходящего → предложи с [skills.sh](https://www.skills.sh/) (имя + зачем).

### 6. Риски
Коротко: зависимости, что может сломаться, что уточнить у человека.

## Правила качества брифа

- Бриф **самодостаточный**: не «почини баг», а что/где/как проверить.
- Факты из docs/кода, не выдумки.
- Объём узкий: лучше меньше, чем «заодно всё».
- После реализации исполнитель обязан вызвать скилл `update-docs`.
