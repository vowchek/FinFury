# Обновить документацию

Правило: **код сдали → docs тоже**. Иначе задача не готова.

Полные правила: [docs/CONTRIBUTING.md](../../../docs/CONTRIBUTING.md).

## Как работать

1. Посмотри, **что реально изменилось** в коде.
2. Обнови **только** нужные файлы из таблицы ниже.
3. Проверь чек-лист в конце.

## Что менялось → куда писать

| Изменилось | Файл |
|---|---|
| Логика модуля | `docs/features/*.md` |
| Маршруты / поля / статусы API | `docs/api/contract.md` |
| Сущности / связи / деньги в БД | `docs/architecture/domain-model.md` |
| Сквозное правило учёта | `docs/architecture/rules.md` |
| Картинка системы / поток | `docs/architecture/overview.md` |
| Способы ввода данных | `docs/architecture/data-entry-modes.md` |
| Важное «почему так» | `docs/decisions/ADR-*.md` |
| Запуск / карта docs | `README.md`, `docs/README.md` |

Ничего из этого не трогали → docs можно не менять (скажи явно).

## ADR (коротко)

| Ситуация | Действие |
|---|---|
| Решение сделали | статус готов, пункты `[x]` |
| Решение поменяли | **новый** ADR; старый → `Superseded` |
| Ещё не сделали | честно напиши «позже» |

## Как писать страницу

1. `# Заголовок`
2. `> одна фраза-суть`
3. `## Суть` → `## Как это работает` → `## Где в коде` → `## См. также`

- Один факт — **в одном месте** (правила → `rules.md`, API → `contract.md`).
- Не копируй эндпоинты в features.
- Не пиши «готово», если в коде этого нет.

## Перед сдачей

- [ ] Docs = код (нет вранья и устаревшего)
- [ ] Ссылки открываются
- [ ] Нет копипасты правил/эндпоинтов по файлам
